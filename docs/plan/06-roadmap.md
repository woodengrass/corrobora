# 06｜實作順序、驗收與停止條件

[索引](../README.md) · [P0](../experiments/p0-first-farm.md) · [P1](../experiments/p1-interface-smoke.md) · 更新：2026-10-22

本庫 P0–P5 尚未驗收；Farm 已有的局部實測另列來源，不重設為零，也不自動算本庫通過。依交付排序，不以估計百分比或固定完成月份冒充進度。

## 0. 近期：MIS診斷與改善案例

MIS 第二波投入問題的首組配對已完成；下一個遊戲里程碑是同協定獨立配對重測，並保留操作說明與有依據的改善結論。這是單機能力案例，先於正式跨農場經驗轉移；不要求先測完所有物品、容量邊界或 W/G 項目。相關來源與適用限制仍須核對，不能省略本次比較需要的環境、守恆、停止及恢復檢查。

Farm [59](https://github.com/hthOG/minecraft-farm-mcp/blob/main/docs/59-mis-idle-input-diagnosis.md) 記錄 C-v2：閒置後補的第二波在固定窗口內仍留入口。Farm [62](https://github.com/hthOG/minecraft-farm-mcp/blob/main/docs/62-mis-idle-strategy-comparison.md) 已固定同條件、最多一次原生續跑的 host 策略比較；[63](https://github.com/hthOG/minecraft-farm-mcp/blob/c7c9ba4a5e62c41f38eb29f420244387e10ef59c/docs/63-mis-idle-strategy-results.md)已報告一次 C-v2 基準與一次 D 策略：12 件／5,000 刻，終點交付 6→12、入口剩料 6→0、原生啟動 1→2，沒有修改紅石。第 3,200 刻是首次固定取樣確認，並非精確到達時間；獨立重複配對為 0。不同投料時點的較早成功不混算重複。

延續這份計畫執行，不另外發明相異的投料時點或門檻。以凍結版本／設定、同來源和可核對初始條件、兩波負載、取樣與 5,000 刻窗口作比較；唯一主要處理差異是是否允許條件式單次續跑。初次探索可使用既有 C-v2 作參考，但結論須揭露不同時間執行與非位元相同的初始狀態；候選凍結後，另從獨立冷還原重跑原版／策略版配對，不把同輪多個取樣點算獨立重複。樣本不足則限縮為個案。

首組比較完成即可先交付操作指南與暫定結論，明示獨立重測待完成；不用等整個里程碑收尾才回報結果。完整案例的獨立重測與樣本限制仍須補齊，一組成功不支持普遍可靠性。

本里程碑以一份完整案例報告收尾：

- 說明輸入／輸出、啟停、批次追加步驟、適用版本／負載，以及來源明載、結構推論、實測與未知的差別。
- 保存競爭假設、事前不同預測、可區分原因的試驗與反例；策略有用不等於作者意圖或完整根因已確定。
- 分列原版／候選交付量、入口剩料、首次固定取樣確認送達的刻數、互動與實驗成本、守恆／保護樣本及中止原因；只報實際量到的指標。
- 交付獨立重測與原始重算／保存／冷還原核對，保留失敗。缺少重複時明示仍待完成，不能只靠一次成功宣布里程碑完成。
- 明確歸類為操作改善、host 自動續跑或紅石結構改善。此輪主要測 host 策略；未改／未測紅石就不稱結構修復。若原版配合正確操作已符合需求，允許維持原版或僅建議操作協定。
- 整理可分享的最小重現包：去敏 runner／純比較器、固定版本與設定清單、最小原始證據與 hashes、重算命令、預期結果及取得遊戲／設計資產的合法步驟。不能公開的原始資料與尚無法外部重跑的步驟逐項列出，不能把 hashes 當成可重現性本身。

本輪同步既有首組結果並補本地離線修正／重播交付；沒有執行新遊戲試驗。純資料契約及 fixture 通過只支持離線流程，不代表自主診斷或改善可泛化。從此案例抽取最小實驗流程，再補正式比較所需世界身分、持久操作紀錄與恢復驗證。選擇性查詢／context 可以逐項移植；它們的效果與機器改善、經驗轉移分開評估。

## 1. P0：正常農場與明確任務

2–3 類候選是 pilot 方向，第一個交付只需一座可合法使用、人工跑通的完整農場。所有候選、排除、是否已見基線／方法成績進 [登記表](../experiments/candidate-registry.md)。

填 [P0](../experiments/p0-first-farm.md)：版本、來源、物料、輸出會計、預熱／窗口、載入／玩家、時間模式及重置。可寫小計數器，不先建資料平台。

後續正式完整農場／跨案例診斷研究的首個模式用 repair_restricted；近期 MIS 仍是 host 操作開發案例。正式研究公開保留介面／結構与修改限制，不洩漏故障；free_optimize 和 design_build 分開。農場、產量門檻與版本待實測，候選數值不冒充定案。

正常版要能核對、重跑波動，變體先人工驗證；簡單對照保留。主張耦合需非 AI 的交互配置測試，不能硬造不存在的瓶頸。

通過：正常版可行、來源可用、會計可核對、波動及未知有紀錄。否則先修環境／候選。

## 2. P1a：不用模型也能重跑

建立真正的 Python／Java 專案和鎖檔，先完成乾淨世界啟停、參考設計載入、固定時間量測、原始結果保存、冷重置，以及獨立 evaluator。

不承諾精確 RNG 回滾；初始庫存、零產出、重複事件、非法注入、重置殘留用小案例核對。

## 3. P1b：固定模型能看到和能做的事

按 [介面](agent-world-interface.md) 與 [工具契約](agent-tool-contracts.md) 建 bootstrap、非語意概要、結構化查詢、切片、分頁、有限 patch、advance、submit_design。能力清單只列已支援項。

驗座標、缺失／空值、同 capture 分頁、stale、讀取不載入、等待期間時間控制、取消／重送／partial、隔離及公平性。W01–W22 的阻擋条件見 [驗收](agent-world-acceptance.md)。

首版結構化＋切片，render 和全面逐 tick profiler 不擋開工；模型自行推定模組，不由工具給正確分解。

## 4. P1c：受控實驗與獨立驗收

加入診斷副本、提交／執行實驗、job 查詢與取消、事前預測或 unknown、sensor metadata、全部重複與成本。父世界、副本、正式驗收隔離。

依 [P1 工作表](../experiments/p1-interface-smoke.md) 跑固定腳本端到端；成功與合法失敗都留存。每步能追到狀態、證據和成本，不只交影片。

## 5. P2：先普通強模型

獨立微型場景教同一份 manual，驗座標、分頁、修改、提交，不教正式故障。工具問題先修共同介面，不只救處置組。

接一個強模型與固定 harness，依資源跑 B0、B1/B2、B3。12–24 個設計×條件只是 pilot 工作量起點，不保證統計充分。記全部 runs、候選缺失、角色對應錯誤、試驗浪費、錯誤重用與成本。

| 觀察 | 下一步 |
| --- | --- |
| 正常版無法正確量測 | 回 P1，不當模型問題 |
| 模型看不懂表示或工具 | 修共同介面／教學，記成本 |
| 單題能解，舊經驗反覆誤導 | 考慮 P3a |
| 候選有用但選測試浪費 | 可獨立考慮 P3b，不需 gate 先贏 |
| 真正原因從未進候選 | 排序救不了，先查觀察／生成缺口 |
| 原始歷史與普通筆記已足夠 | 簡化方法，保留簡單案例，不挑題直到方法贏 |

## 6. P3a：只測重用檢查

依 04 凍結模型／validator 責任、reuse_plan、檢查上限、證據範圍及回退。先合成紀錄驗 G01–G08，再真實農場做 I0 提示、I1 證據、I2 證據＋規則。

共同方案、檢查及成本明確，不免費取得真值；I1/I2 同證據仍有差異才談 gate 增量，不靠遵守率自證。誤擋、回退及修復路徑均記，安全不隨 gate 關閉。

本階段通過代表方法可比較，不代表正式假說成立。

## 7. P3b 選測試；P3c 組合

固定候選池比最便宜、自由選與 S1，測重複／改寫／窄區間／真原因缺席。看後續功能及成本，不只分歧分數。

有理由才合併並做 2×2。不一次加信念圖、技能治理、更多模型與自我重寫來混淆作用。

## 8. P4：正式跨農場研究

凍結選題／排除、方法、模式、split、觀察、預算與分析。先 E1 再按資源 E2，I/S 局部組不能代替 B1/B2/B3。

新案例不能只是平移，按同家族新條件、未見組合、跨家族分層；困難子集與預定可行候選都報。Agent 或研究者不看正式 probes 調參。

按 05 報成功、受限達標成本、預測、負遷移及區間，全部失敗和人工協助保留。

## 9. P5 與後續

free_optimize 研究允許重建的效率；design_build 不提供完整起始藍圖，研究初始設計和迭代。保留完整自主農場目標，但不是首個 gate 實驗前置；成果名稱依實際完成模式。

跨遊戲版本、跨模型接棒、工具治理、完整生存與流程級 RSI 需獨立問題。第一輪不先做大型資料庫、全量語料、Web UI、多 Agent 或訓練。

## 10. 停止與狀態更新

沒有可重現問題不建方法；多算力才有效就匹配；近重複才有效就縮限主張；波動較大先修量測；新題改善卻害舊題記回歸。

強模型吸收方法收益時如實報告並簡化，不削弱基線。狀態更新需真實命令及紀錄，寫入 09；本次只補規格，不把 P0、P1 或 CDET 標成完成。
