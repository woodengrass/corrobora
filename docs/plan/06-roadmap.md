# 06｜實作順序、驗收與停止條件

[索引](../README.md) · [P0 工作表](../experiments/p0-first-farm.md) · 2026-10-02

所有階段尚未完成。里程碑表示工作依賴，不是預定日期；先用 pilot 的實際執行成本與人力估算，不承諾未量測的完成月份。

## 1. 第一個交付不是記憶系統

先讓一座正常的完整農場在固定環境運行，取得可以重跑的產量分布。再建立可用程式修改、測量與驗收的環境，最後才讓 Agent 進來。

不禁止為 P0 寫小型計數或記錄程式；限制的是在問題尚未成立前，先建完整資料平台、記憶生命週期或複雜多 Agent 系統。

## 2. P0：選題與量測

填 [第一座農場實驗表](../experiments/p0-first-farm.md)，交付：

- 一個來源與使用權限清楚的正常參考設計，附精確環境配置。
- 公開任務草案：合法輸入、輸出端、允許操作、資源／區域限制、成功指標。
- 不含 AI 的多次參考運行紀錄，據此決定預熱、量測窗口與可辨認的差異。
- 少量原因不同的實測變體，以及不受影響的正常控制案例。
- 建置與觀察所需的介面清單；哪些必須寫 mod，哪些現成能力已足夠。

甘蔗／竹子等作物農場只是候選，不是已選定或已驗證資料集。不能因為計畫需要多個瓶頸，就把正常負載下不會出現的瓶頸說成真實失敗。

**通過條件**：正常版確實可運行；輸出計算方式可被人工核對；量測波動、來源限制與未知項有紀錄。未通過時調整環境／農場，不開始大規模 Agent 實驗。

## 3. P1：最小可執行環境

按以下依賴逐一完成，而非同時開發所有工具：

| 次序 | 工作 | 驗收 |
| --- | --- | --- |
| P1a | 固定伺服器配置，由乾淨世界啟動／停止 | 版本與設定可重建，前次庫存與實體不殘留 |
| P1b | 載入參考設計、限制區域的 patch、固定 ticks 運行 | 合法修改成功，越界／過期 revision 被拒絕，失敗有紀錄 |
| P1c | 輸出與必要中間觀察、原始事件與成本 | 已知小型案例的計數正確，事件可定位，不靠模型解釋計分 |
| P1d | 獨立驗收與診斷副本隔離 | 注入物品不會提高正式成績，Agent 不能改評分器 |
| P1e | budget、取消、逾時、錯誤分類與封存 | 中斷也留下完整成本與原因，不默默重跑成成功 |

先採可驗證的冷重啟與世界副本，再評估更快快照；不承諾任意 tick 的精確回滾。工具名稱和契約見 [03](03-farm-testbed.md)。

P1 完成時，即使完全不接模型，也應能依一份 manifest 自動完成：建立世界 → 載入農場 → 預熱 → 量測 → 封存 → 重置。實際命令要等程式建成後才寫入 README，不能把本計畫中的描述當已存在腳本。

## 4. P2：強基線與問題確認

先接一個強模型與固定的一般執行框架，跑 B0–B3。先用少量案例排除工具問題，再擴到約 12–24 個「設計×條件」候選案例作 pilot；這是工作量起點，不是統計充分性的保證。

先看哪些失敗真的出現：

| 觀察 | 接下來的研究方向 |
| --- | --- |
| 正常農場也無法被正確量測 | 修環境，不解讀成模型失敗 |
| Agent 不能辨認結構或合法操作 | 先修工具契約／任務難度；不要急著加跨題記憶 |
| 單題能解，但給舊經驗後反覆誤判 | 值得研究適用性與錯誤重用 |
| 找得到原因但浪費大量試驗 | 值得研究測試選擇與停止時機 |
| 候選原因始終沒有真正原因 | 優先研究候選生成／觀察缺口；排序不能補救缺失候選 |
| 原始歷史與普通筆記已同樣有效 | 刪減特殊方法；保留有價值的比較與適用邊界 |

交付每次 run、失敗分類、成本拆解、可重跑範例及進入 P3 的理由。不能只憑一段對話或單次失敗決定方法。

## 5. P3：最小方法與消融

依 P2 的失敗原因選擇 [04](04-experience-method.md) 的最小子集。若重用傷害明確，先做前提檢查；若主要是試驗浪費，先做固定候選池的選擇比較。不要為了符合原先構想，把 gate、圖譜、工具生成與記憶治理一次全加上。

至少能切換普通結構化筆記、額外適用性檢查與測試選擇。方法的額外預測、反思、維護及測試成本全部記錄。與最接近文獻的可執行方法／明示改編比較，不能只勝過 Fresh 就宣稱新方法有效。

**通過條件**：在 dev 有值得正式檢驗的效應，核心差異與消融可解釋，成本公平且方法已凍結。通過不代表正式假說已成立。

## 6. P4：正式跨農場研究

依 [05](05-evaluation-protocol.md) 鎖定主要比較、split、預算、指標、排除政策及分析。先完成相同歷史 E1，再按資源進行自主累積 E2；兩者的結論不能混用。

正式資料包含未見條件或組合、適用與不適用經驗、多個順序／獨立重跑，以及必要回歸控制。樣本規模由 pilot 變異與可負擔成本決定。

交付成功率、受限達標成本、預測／診斷、負遷移與不確定性；不只報最好模型或成功案例。方法無優勢時保留結果，但仍須判斷證據是否足以支持新的實證結論。

## 7. P5：從需求設計完整農場

在同樣的合法資源、工具與評分邊界下，移除完整起始藍圖，要求提出可運行設計。必要的遊戲世界與合法初始物料仍按公開規格提供，不把空白地形等同從零先驗。

分開量測初始設計品質、迭代後品質、總成本與跨題經驗效益。只有完成這階段並取得相應證據，才使用「自主農場設計」作成果主張；前面只完成維修時，題目要明確写診斷與改良。

## 8. 縮減／停止規則

沒有可重現問題就不建候選方法；只有額外算力收益就先做匹配；只有近重複藍圖收益就限制遷移主張；波動大於效應就先改善量測；新任務變好而舊任務退步時，將回歸列為失敗而非隱藏。

新模型已吸收收益時，重新報告方法適用範圍。真正值得保留的可能是測試環境和實證，不必為了保住架構不斷增加難以理解的模組。

## 9. 第一輪不做

不先建 PostgreSQL／Qdrant／Neo4j、全量來源攝取、龐大機制圖、Web 產品介面、領域模型訓練、任意 GitHub 程式安裝、多 Agent 協調或 harness 自改。生成分析腳本可以是工具使用，不另膨脹成第二個研究。

跨版本、跨模型記憶接棒、完整生存操作與流程級 RSI，待主結果成立且有獨立問題後再規劃。這些不是被新文件偷偷排入的未來承諾。
