# 研究問題、強基線與貢獻判準

> 2026-10-01。現行任務是完整農場工程，不再以問答檢索分數作主要成效。所有假說待測。

## 1. 研究問題

| 問題 | 可反駁的假說 | 主要證據 |
| --- | --- | --- |
| RQ1 經驗何時有用？ | 相關經驗在部分條件降低新農場的診斷／設計成本，也可能造成負遷移 | B0–B2，在有效／無關／誤導性相似情境的成功與成本差 |
| RQ2 條件式重用是否有額外價值？ | CDET 在相同可用證據與預算下，改善普通筆記／raw history／固定診斷的成本—品質取捨 | B4 vs B1/B2/B3，held-out 與消融 |
| RQ3 測試選擇與修正是否更可靠？ | 方法更準確預測干預结果、更少誤修，且保留未受影響能力 | 預測記錄、完整重播、舊任務回歸與局部修正比較 |
| RQ4 改善是否能跨設計與模型？ | 效益不只存在於同藍圖變體或單一模型 | 留出 lineage／組合／條件；模型內配對比較，允許效益消失 |

先完成 RQ1/RQ2；RQ3 提供機制證據，RQ4 依資源擴展。沒有被量測的項目不放入結論。

## 2. 基線 B0–B4

| 組別 | 定義 | 角色 |
| --- | --- | --- |
| B0 Fresh strong agent | 每題無跨題歷史；同工具、模型與當題 budget | 測經驗有無的輔助基準，不是唯一主要對手 |
| B1 Raw-history strong agent | 可搜尋／閱讀全部允許的原始實驗紀錄與設計；不加專用經驗結構 | 主要強基線；上下文放不下可分段工具閱讀，不能粗暴截斷 |
| B2 Ordinary notes / skills | B1 的資料權限＋普通摘要與可重用技能；可自由反思、檢查條件 | 判斷一般記憶是否已足夠；維護成本計入 |
| B3 Fixed diagnostic workflow | 同原始資料＋在 dev 階段凍結的合理人工檢查順序 | 排除複雜方法只是在重現一張檢查表；開發人力另列 |
| B4 CDET | 同原始資料＋16 的條件式重用、候選測試排序與局部修正 | 待評估方法，不預設最佳 |

各組共享模型版本、一般 harness、觀察／行動權限、來源快照、限額與重試政策。只有明確宣告的 representation／controller／prompt 改變。不可限制 baseline 自發使用本方法也會用的推理。

分開做「同一凍結歷史的表示／使用方式比較」和「各組自行成長的端到端 stream」；不能既讓各組蒐集不同經驗，又宣稱效果只來自表示法。操作見 12。

與相近公開方法比較時，能跑官方實作就先復現；改編成農場工具介面的版本須標 adaptation，記差異与調參預算。只看摘要的提示詞模仿不能稱官方方法復現。

## 3. 任務組織

每個設計家族安排：首次調查、舊機制適用、經驗無關、表象相似但前提不符、未見組合與修正後回歸。分類由研究者依可驗證機制標註，標籤不提供給 Agent。

完整農場含自然發生的設計失敗，也可加入可控故障／限制作診斷。受控故障、天然缺陷、合法條件變化分層報告，不把人造難題冒充真實部署分布。多個原因並存或觀察不可辨識的題允許多解／unknown。

`repair_optimize` 與 `design_build` 分開評分。前者可有很強的診斷結果，但不能作為從零設計能力的證據。

## 4. 主指標

**共同主結果是固定 budget 下成功率，以及達到指定品質所需的成本分布。** 不能只比較成功案例的平均成本，淘汰失敗任務會造成倖存者偏差。

| 指標 | 定義／注意事項 |
| --- | --- |
| `success_at_budget` | 通過凍結 evaluator 的 episodes／全部指派 episodes；timeout、無效輸出留在分母 |
| `cost_to_threshold` | 到首次獨立確認達標的累计成本；未達標者記為截尾，不當成零或直接刪除 |
| 品質—預算曲線 | 各固定預算節點的成功與有效工程品質；報所有 runs，不只最佳設計 |
| 預測準確性 | 執行前鎖定的可量測預測與結果比較；區間寬度、覆蓋與 unknown 分開 |
| 診斷／修復 | 可識別原因集合的吻合、錯誤修改、修復後完整重播；多解不硬判唯一原因 |
| 負遷移 | 配對條件下，有經驗的成功下降或成本升高；同時報有益、無差異與有害比例 |
| 回歸 | 修改經驗／程序後，未受影響的舊設計或條件是否退步 |
| 工程品質 | 合法產出、可靠性、footprint、材料與其他已宣告限制；不任意改綜合權重 |

成本分列模擬 ticks、試驗次數、工具呼叫、input/output/cached tokens、API 支出、牆鐘、記憶維護與人工時間。不同粒度的測試不能只比較次數；沒有預先固定的權重就不把各種成本加成一個分數。

如要單一配對效應，預先指定一個主預算軸 B，用 `E[min(T, B)]` 比較到成功的受限成本，未成功者在該軸貢獻 B，並與 `success_at_budget` 共同解讀。其它軸仍完整報告，不把低品質的省錢當優勢。

## 5. 消融與新增價值

至少比較：結構化紀錄本身、適用性 gate、測試選擇、局部修正。資源允許時用 gate×selection 的 2×2 設計；每次只移除指定方法，不移除原始資料、安全或必要的版本約束。

另用固定候選假說／實驗池比較排序；否則「更好的候選」和「更好的選擇」會混在一起。可加 cheapest-first、random-valid、強模型自由診斷作为簡單選擇基準。

學習曲線用固定未見 probes 與獨立 repeat 比較，不把後面任務較簡單當進步。經驗被取回／引用的次數只能描述行為，不能當作因果效果。

## 6. 原有資產怎麼用

舊 `benchmark/gold_dataset/` 是問答、機器推薦與資料攝取回歸資料，不是可執行農場評測。詞典／GTMC／目錄可作可用資料，公開性與版本需記清；不得用已有目錄筆數冒充 farm case 數，也不能把全部來源算成已驗證機制知識。

新農場資料將來另建 manifest、設計 lineage、量測與 runner。來源藍圖及網路存取權限在各組一致；至少主實驗採凍結來源，開放網路另列，避免隨時間變動的資料污染比較。

## 7. 貢獻成立與不成立的例子

- 成立的候選：新的可重現評測揭露條件性負遷移；具體選測試方法在強對照下穩定改善；或嚴格證明某複雜模組無必要。
- 不足：新命名的記憶欄位、只比 Fresh、幾座成功影片、只報最好一次、更多算力造成的收益。
- 限制：只在少量 family 或單一模型有效，就只主張該範圍；沒有方法增益不等於評測與負結果一定可發表，仍需完整性與新資訊。
