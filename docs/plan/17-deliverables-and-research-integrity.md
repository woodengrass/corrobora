# 交付物、研究風險與科展準備

> 2026-10-01。目的是得到可檢查的資訊科學研究，不預先承諾論文、得獎或國際賽資格。本文件是本計畫的研究建議，不取代任何賽事當年度規則。

## 1. 第一個專案的交付物

| 交付 | 最少內容 | 尚不能宣稱 |
| --- | --- | --- |
| 可執行環境 | 合法完整農場、重置／建造／量測／評分、版本與來源 manifest | 可代表所有 Minecraft 生電機制 |
| Pilot 與強基線 | B0–B3、所有失败、成本拆解、可重現失敗模式 | 已證明候選方法有效 |
| 候選方法 | CDET 契約、controller、版本化 prompts、適用性／選測試／修正消融 | 原創性僅靠命名或組合功能成立 |
| 正式結果 | held-out、配對與獨立重跑、CI、負遷移、限制 | 更強模型永遠需要此模組 |
| 可展示研究軌跡 | 原始觀察、事前預測、下一測試理由、設計 patch 與獨立評分 | 一段成功影片等於統計證據 |

維修／改良與從零設計分別標示。若只完成前者，題目與摘要應使用「診斷與改良」，不能寫已完成自主農場生成。

## 2. 可能的研究敘述

工作題目可用「跨任務診斷經驗對自主工程 Agent 效率與負遷移的影響」，Minecraft 作實驗平台。

真正要回答的是：哪些經驗可跨設計使用、前提不符時如何辨識、診斷試驗是否更省、修正是否保留有效能力。可泛化性來自受控任務與方法比較，不是把標題中的 Minecraft 刪掉。

若只有環境／基線完成，研究定位就是評測與實證；若方法也有效，才加方法貢獻。沒有方法優勢不表示資料自動足以發表，仍要提供新的可靠資訊。

## 3. 關鍵風險與應對

| 風險 | 應對／停止條件 |
| --- | --- |
| 更強模型自行解決同一問題 | 模型內配對重跑；保留哪些條件仍需要方法的證據，無優勢就簡化 |
| 重造既有方法 | 依 13 讀最接近全文／程式；改編與原創部分清楚分開 |
| 環境工程吞掉全部研究時間 | 固定版本、先 2–3 類候選、先完整農場改良；不先做視覺導航／完整資料平台 |
| 藍圖記憶冒充機制遷移 | lineage／組合切分，凍結來源，保留相似但前提不同的案例 |
| Agent 利用評分器漏洞 | 獨立 evaluator、新世界重播、合法物品 accounting、權限隔離 |
| 方法只靠額外算力取勝 | 總 budget 與當題 budget 兩種視角，維護成本全部計入 |
| 一次測試被誤寫成普遍規則 | 可反駁預測、scope、反證與版本；多解／unknown 不強迫猜測 |
| 任務數多但有效樣本少 | family／stream 分組分析，不把相關 ticks 或微小變體當獨立樣本 |

## 4. 研究日誌與獨立性

每次變更記日期、研究者決策、理由、代碼／prompt hash、看到哪些 dev 結果、是否接觸過 held-out、AI／教師／同儕協助範圍。正式資料開封後的修改應產生新研究版本，不能混入原先假說的驗證結果。

保存失敗提案、無效消融與被否證假說；不要只留最後有效的參數。原始評分不覆寫，分析修正另記版本。AI 可以協助程式與文案，但研究者需能解釋實驗、模型限制、統計單位、資料來源與每個重要決策。

科展或其他賽事的註冊、審查、AI 使用揭露、參賽時程與資格，正式報名前另查当年度官方規定；本輪沒有替使用者報名或假定符合資格。

## 5. 展示不是替代實驗

展示可以選一個有代表性的成功案例和一個方法失敗案例：同初始條件下，呈現各基線的候選原因、所選試驗、觀察、patch 與最終結果。視覺化只用已保存紀錄；不要現場生成一段無法對應原始 log 的漂亮推理。

答辯至少能回答：

- 為什麼這個測試能區分原因？哪些情況無法區分？
- 差異来自新方法、更多資料、更多算力，還是較好的工具？
- 什麼叫完整農場？哪些是人工輔助或受控故障？
- 既有方法已做什麼？本研究增加了哪項可檢查的結果？
- 哪些 family／模型有效，哪些無效？能否由他人重跑？

## 6. 下一個可執行決策

先完成 P0：選定可授權、可運作的候選農場，寫成功門檻與測量規格；接著建 P1 並跑強基線。尚未看到穩定失敗模式以前，不開發大型治理圖、不做模型訓練、不為預想結論投入任意長的 autonomous run。

需要預算時先用 pilot 的實際模型用量、simulator 時間與人工標註成本估算，不引用過期產品價格，不承諾固定完成月份。
