## 1. 本輪可確認的狀態

本輪以修訂前 `main` commit `47d29ac26611c4aaa9327aa072bc92895b29f800` 的 repository 為盤點起點。可確認根目錄只有文件、原始資料與既有評測素材，沒有 Corrobora Python application、Java farm adapter、農場 runner 或正式研究結果。

此次工作是文件重建與舊參考清理，不是 runtime 實作。所有 P0–P5 尚未驗收；第一座農場、正式版本組合、成功門檻、預算與模型仍待實測決定。

舊的來源計數是歷史盤點，不作本輪全量資料審核。machine catalog 不代表擁有可运行藍圖；原始術語與文章也不是已驗證的機制模型。`benchmark/gold_dataset/` 仍是舊問答／資料管線 fixture，不是新農場 gold。

## 4. 最終交付物

### 可執行環境

自建／授權的完整農場、世界和設定 manifest、建造與診斷工具、固定驗收、可重跑指令及限制。完整 farm 是必要範圍，修復／改良與從需求設計分開標示。

### 研究資料與分析

逐次 run、事前預測、設計 patch、原始觀察、成本、失敗與排除原因；清楚的 split、acquisition history、對照、消融、統計與不確定性。保留成功與失敗，不以漂亮演示代替樣本。

### 方法或實證結果

若方法有效，指出新增決策與相對強基線的收益；若普通歷史已足夠，清楚限制方法必要性。若只有測試環境與新失敗分類，就按評測／實證研究定位，不把計畫中的候選機制寫成已發明。

### 可讀的說明與答辯材料

解釋研究問題、最接近先例、你實際完成的部分、為什麼測試公平、哪些結果仍無法判斷。展示案例必須能回到原始紀錄；視覺化理由不能事後偽造成模型事前預測。

## 5. 研究日誌格式

每次重要決策至少記：日期、研究者、問題、候選做法、看到哪些 dev 資料、選擇與理由、程式／prompt／資料 hash、是否接觸 held-out、AI／教師／同儕協助、下一個可推翻此決定的測試。

正式方法凍結後的修改另立版本。若研究者已看保留結果並据此改方法，該資料轉為開發資料，需要新的獨立評測，不能仍稱第一次保留驗證。

保存無效方法、刪除模組和負結果的理由。文件刪除舊規劃，不表示未來可刪除不利實驗證據。

## 6. 科展與研究獨立性

這個計畫可以形成實證、評測或方法研究，但本文件不保證入選、得獎、國際賽代表或論文接受。賽事適用年度的資格、時間、預先審查、AI 使用揭露與指導限制，在報名前另查官方規則；本輪没有逐項審核參賽資格。

研究者應能獨立解釋：遊戲機制與量測、為何某個實驗能區分原因、成本公平、樣本不是獨立的情況、既有研究已做什麼，以及模型和方法各自造成什麼差異。使用 AI 協助程式與文字不等於已完成獨立的研究決策，需記明協助範圍。

## 7. 主要風險與處理

| 風險 | 處理 |
| --- | --- |
| 更強模型直接解決 | 模型內配對重測；無淨收益就簡化 |
| 只是在拼裝已有方法 | 讀最近全文、對照與消融；不以縮寫當創新 |
| 環境工程吞掉研究時間 | 一個版本、先冷重啟、少量完整農場；不先生存操作和 Web 介面 |
| 不存在的瓶頸／可識別性 | 人工 reference 和受控試驗確認；多解與 unknown 保留 |
| 更多資料或算力造成表面優勢 | 共用原始證據與完整成本；兩種預算視角 |
| 舊經驗誤用、修正傷害舊功能 | 相似不適用案例與回歸控制 |
| 評分漏洞與資料洩漏 | 工具權限、診斷副本、獨立新世界與固定 evaluator |
| 基於摘要過度推論新穎性 | 依 08 標閱讀深度；正式比較前補全文與實作 |

## 8. 現在第一步

打開 [P0 工作表](../experiments/p0-first-farm.md)，選一個可實際運行的候選，填合法輸入與輸出端，跑一次人工 reference 並保存配置與原始結果。接著重跑、量出波動，再判斷窗口與下一步。

完成這個最小證據閉環，比繼續增加假說模組或資料庫欄位更優先。尚未有實測資料時，狀態維持 P0／規劃，不能寫 baseline 已通過。
