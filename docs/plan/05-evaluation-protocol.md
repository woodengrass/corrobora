# 05｜基線、機制比較與長期實驗協定

[索引](../README.md) · [方法](04-experience-method.md) · [世界介面](agent-world-interface.md) · 更新：2026-10-08

全部待執行。正式指標、樣本量、任務與排除規則在 pilot 後、保留集開封前鎖定。不同問題用不同實驗回答，不用 B4 勝過 B2 就宣稱全部機制有效。

## 1. E1 與 E2 的問題不同

E1 相同歷史：共同採集策略取得不含測試答案的原始設計、操作與觀察。相關組有同一入口，可生成各自摘要，整理和工具／檢查成本均入帳。人工或共同模型採集需明示，不稱本方法自主成長；用多種歷史來源檢查偏差。

E2 自主累積：各組從相同資產出發，按自身決策完成任務與維護經驗。不同後續歷史是整體效果的一部分，不只歸因表示法。不得互讀各組歷史或免費取得最好一組的完整庫。

先小型 E1 與局部比較，再擴大 E2。跨農場收益、模型權重訓練與 RSI 分開。

## 2. 端到端基線 B0–B4

| 組 | 配置 | 目的 |
| --- | --- | --- |
| B0 Fresh | 同模型／工具／當題預算，無跨題歷史 | 經驗有無的輔助比較，不是唯一對手 |
| B1 Raw research | 允許的全部原始歷史，可搜尋分頁、當題筆記與工具 | 不能因放不下一次 prompt 就截斷 |
| B2 Ordinary notes | B1 權限＋模型自行整理的摘要／技能 | 不是人類免費整理的最佳筆記 |
| B3 Fixed workflow | 同資料＋在 dev 凍結的合理檢查表 | 人工成本另列，排除簡單流程即可解決 |
| B4 Candidate | 同資料＋當輪宣告的 CDET 子集 | P3a 先 gate；排序另外版本／驗證 |

各組都可正常反思、檢查條件、寫受限工具，不禁止基線合理推理來保證勝出。正式方法比較需至少一個最接近且可取得的既有方法，官方實作、改編、提示詞仿作分開，記訓練／移植／調參成本。文獻閱讀限制見 08，不依名稱宣稱已復現。

## 3. I0–I2：分開提示、證據與強制規則

E1 內的局部實驗不取代 B1/B2/B3。共同流程在分組前生成並凍結相同 reuse_plan、前提、位置、程序和檢查，不以私有故障答案補完。

| 組 | 得到什麼 | 固定程式做什麼 |
| --- | --- | --- |
| I0 提示 | 相同經驗、前提與檢查建議 | 模型自行決定是否查及如何重用 |
| I1 證據 | 指定檢查結果與相同診斷資訊 | 不強制研究 gate，由模型決定 |
| I2 證據＋規則 | 與 I1 相同檢查結果及呈現 | 依 04 固定政策准用、補查或退回 |

I1/I2 從同一父狀態取同一份前置檢查結果，檢查在副本進行，不只對一組改變父世界。不能精確重現時，採配對初始化及獨立重跑並報限制，不宣稱完美反事實。

即使工程上共用一次觀察，各組仍按獨立取得它的成本計帳；共同生成費用完整報告，不當免費 oracle。總預算含檢查，不給 I1/I2 額外後續試驗。

I1−I0 反映指定檢查與新證據的組合，不是無假設的純資訊效果；I2−I1 比較固定 gate 增量。拒絕訊息改變模型後續推理也屬政策作用，不宣稱隔離單一心理機制。

主要看完整修復成功、總成本、有效程序誤擋、錯誤放行、回退與重建。遵守率只證明執行，因 I2 被強制，不能自證研究有效。沒有獨立適用性標註時不虛報真實適用率。

## 4. S1：獨立比較測試選擇

固定世界、歷史、假說、預測區間、候選測試及後續行動表，只換最便宜、模型自由選和分歧排序；按資源加 random-valid。生成／選擇各自計費，人工真值候選另標 oracle-assisted。

必測完全重複、排列／改寫、過窄區間、真原因缺席。改變決策不是主要收益：確認原方案也有用，改主意也可能更錯。小型 dev 分叉比較不同測試與不測試的後續品質和總成本；分析分支不回流正式 Agent。

有理由時才合併 gate 與排序，做 2×2 及交互作用。不能因整套有效就宣稱每部分有效。

## 5. 觀察、工具與成本公平

固定 model/snapshot 或 API 時段、推理設定、context、通用 harness、bootstrap/manual/schema、sensor、切片、資料精度、載入／時間模式、來源與區域。結構化、額外視覺、人工模組圖分配置。

同樣的獨立工具教學不含正式答案。B4 不多拿人工標記、流量感測、未公開資料或免費 profiler；觀察缺失不能只替一組人工補答案。

主配置 step_controlled，避免模型較慢使農場多跑；real-time 另列。服務無固定 snapshot 時交錯各組，記日期和限制。

不同 prompt／controller 是明示處置；共同最低可檢查輸出一致，額外前提、反思與預測的成本／行為改變也計入。

同時報硬總預算（含經驗取得／整理／檢查）和同當題預算（另列建置維護）。tokens、API 費用、simulated ticks、查詢量、工具次數、wall time、人工時間分開，不任意相加。快取另列，人工標註不當零成本。

## 6. 選題、切分與困難子集

候選先進 [登記表](../experiments/candidate-registry.md)，記來源、可行性、量測、全部基線、去留及是否已見方法結果。

工程／來源排除與模型容易解決分開，後者保留簡單控制。預定可行候選集和困難子集都報；無抽樣框架不稱代表所有農場。困難篩選靠獨立基線重跑，不挑一次偶然失敗。

探索期允許調整但全留紀錄；確認期凍結生成／篩選與方法，使用独立新案例。不按 CDET 輸贏判可測性、耦合或不適用。

dev、acquisition、held-out 分開，依 lineage、機制組合、原藍圖與條件分組；平移、鏡射、微小縮放、轉載不可跨 split。同家族新條件、未見組合、跨家族轉移分層，少數家族不支持任意泛化。

自然缺陷、人造故障、合法條件改變分開；簡單／耦合由獨立量測決定。repair_restricted、free_optimize、design_build 分開，不事後只留局部修復的成功資料。

模型可能預訓練看過 Minecraft，不宣稱零先驗；主比較凍結共同來源，open-web 另測。

## 7. 時間邊界與 probes

```text
載入公開任務與允許歷史 M(t-1)
-> 觀察／提交預測或 explicit unknown
-> 有界實驗／修改／公開開發回饋
-> 凍結設計及 trace
-> 隔離保留驗收並封存分數
-> 只從允許公開證據更新經驗
-> 有界維護並封存 M(t)
```

工程需要公開回饋，但正式 labels、seeds 和驗收結果不回流模型或研究者調參。提交频率與成本先定，不用 hidden evaluator 當優化器。

固定 checkpoint 凍結經驗，對同一未見 probes 做當題調查但不寫回 acquisition。正式結果方法凍結後統一分析；研究者看結果改方法也是洩漏，需把原 test 轉 dev 並取得新測試。

## 8. 主要結果與解释

共同主結果是 success_at_budget 及達標成本分布；合法未成功、timeout、無效設計都保留，不只比成功者成本。

指定主預算軸 B 時報 `E[min(T, B)]`：T 為首次獨立確認達標的成本，未成功者視為 T>B，零成本放棄不能變成省錢勝利。成功率和其他成本軸一同列出。

若只在最終驗收一次，不能虛報首次達標時間；明示最終成功，或按固定 checkpoint 離線盲評已封存設計估計首次確認。額外評分成本單列，不能回饋模型。

次要結果：事前預測／區間寬度／覆蓋與 unknown、可辨識原因、錯誤修改、負遷移、回歸、資料覆蓋、工具錯誤、累積修改成本與策略路徑。引用經驗次數不是收益，修好不代表原因唯一。

## 9. 統計、失敗與再現

pilot 估效果、波動、獨立任務量與成本，正式樣本按最小有意義差異與可負擔重跑決定。先鎖主比較、預算軸、門檻、非劣性界線（若用）、多重比較與停止規則。未顯著不代表等效。

同農場變體、共享記憶的 stream、ticks 和物品不是獨立樣本。以 family／stream replicate 分組作配對 bootstrap 或合理階層分析；家族太少只報該集合，不假造廣泛母體區間。

配對初始快照／seed 不保證動作不同後亂數相同。多順序與獨立初始化重跑；保留工具／模型／解析／取消／無法辨識等紀錄。排除與重試事前定義，人工救援另列不算自主成功。

manifest 保存 git/config/source/task/split hashes、game/JDK/mod、state、model/API、prompt/manual/schema、arm、時間／sensor、順序、預算、經驗前後版本、全部操作／觀察／結果／成本。公開可授權的逐次結果、排除理由、分析及重跑說明，不散布未授權資料。

新模型須模型內重跑主要組，不拿舊基線對新處置。最近對照依 08 查核；沒有方法優勢也保留結果，不假定所有負結果必然可發表。
