# 05｜基線、長期實驗與統計協定

[索引](../README.md) · [研究問題](01-research-questions.md) · 2026-10-02

尚未執行。正式設計在 pilot 後、保留集開封前鎖定。此文件刻意不預填成功百分比、正式樣本數或勝利門檻。

## 1. 先回答兩個不同問題

### E1：相同歷史，怎樣使用比較好？

先以共同採集策略取得一份不含測試答案的原始歷史，所有相關組都能搜尋與閱讀。各組可按規格產生自己的摘要或結構，寫入、整理與工具建置成本均計入。

這主要比較表示與使用方式。若歷史由人類、固定策略或多個模型取得，要標清楚，不能稱為本方法完全自主成長的結果。用多個來源歷史重複，可降低單一採集者的偏差。

### E2：各組自行累積，長期結果如何？

相同起始資產，各組獨立完成一串任務並保存自己的經驗。它們選不同實驗會產生不同資料；這是整體方法效果的一部分，不應再宣稱只測到 schema 效應。

不得讓一組讀另一組的經驗，也不得把最完整處置組的資料庫免費送給其他組，除非明確另做 E1。E1 先於大規模 E2，避免同時改變太多因素。

## 2. 基線

| 組 | 配置 | 要排除什麼 |
| --- | --- | --- |
| B0 Fresh | 同模型／工具／當題預算，無跨題歷史 | 經驗有無的輔助效果；不是唯一主要對手 |
| B1 Raw research | 可搜尋全部允許原始歷史，分段讀取、當題筆記、一般推理與工具 | 原始證據已足夠的可能性；不能因塞不下一次 prompt 就截掉資料 |
| B2 Ordinary notes | B1 資料權限，另可自主維護普通摘要／技能 | 普通記憶是否已足夠；不是由人類免費整理最佳答案 |
| B3 Fixed workflow | 同原始資料，加在 dev 凍結的合理診斷檢查表 | 複雜方法是否只是重現簡單流程；人工開發成本另列 |
| B4 Candidate | 同原始資料，加 04 的候選方法 | 測額外結構與控制策略的淨收益，不預設最佳 |

B1 可採用分頁原文＋導航摘要的強檢索設計，參考 JAM 的研究方向，但自製實作不能稱為復現其受訓模型。JAM 的驗證層級見 [08](08-related-work.md)。B1 不需故意禁止符合本方法的正常推理。

正式方法比較還需選至少一個最接近、可合理取得的已發表方法作對照。優先讀 SciCrafter 的知識／實驗流程及 ReMe／MCMA；若主貢獻在選實驗，再評估 EvoSCM。是否可執行、模型訓練成本和移植差異在 P3 鎖定。無法復現時寫明缺口；提示詞模仿只能稱 adaptation。

## 3. 公平條件

同一比較固定 model snapshot／API 時段、推理設定、context 上限、通用 harness、工具精度、觀察與操作權限、來源與初始世界。模型服務不能固定 snapshot 時，交錯執行各組，保存日期與設定並報限制。

不同表示法、prompt 和 controller 是明示處置，不必謊稱 system prompts 完全相同。不得額外開放處置組私有標籤、人工模組圖、更多檢索來源或免費自寫 profiler。

報兩種預算視角：包含經驗建置的硬總預算，以及相同當題預算但另列建置／維護成本。API 金額、tokens、simulated ticks、工具呼叫、牆鐘和人工時間分開，不任意混成一個數字。相同試驗次數不一定代表相同成本。

## 4. 任務與資料切分

建立 dev、experience acquisition、held-out evaluation 三個角色。按設計 lineage、來源藍圖、機制組合與操作條件分組；平移、鏡射、小幅縮放與轉載不可跨 split。

分層報告同家族新條件、未見組合與不同家族的轉移。2–3 類只適合 pilot，不足以支持任意生電家族的泛化結論。

安排經驗適用、經驗無關、表象相似但前提不同，以及修正後舊情境回歸。分類要有環境測試依據，不能由是否讓 CDET 勝出倒推標籤。保留自然失敗與可控診斷例，分開報人造故障、天然缺陷、條件改變。

Minecraft 可能存在預訓練知識與現成藍圖；不宣稱空白先驗。主比較採凍結且授權清楚的資料，開放網路另作實用性設定。自建變體降低近重複，但不證明已排除預訓練污染。

## 5. 每一步的時間邊界

```text
載入公開任務與 M(t-1)
→ 觀察、記錄最低必要預測、試驗、修改
→ 取得固定的公開開發回饋
→ 凍結設計與 trace
→ 隔離 evaluator 在未見條件驗收
→ 封存 final score，不回流 Agent 或方法調參
→ 只由允許的觀察／公開回饋更新 M(t)
→ 維護完成或耗盡配額後進下一題
```

不能完全禁止工程迭代回饋，也不能把 held-out evaluator 當無限優化器。兩種回饋的內容、頻率與權限預先寫入 manifest。

在固定 checkpoint 凍結經驗並測同一組未見 probes。probe 內可正常做 task-local 學習，但不能寫回 acquisition stream。正式 probes 的結果在方法凍結後統一分析；研究者邊看邊改仍是 test leakage。

## 6. 共同主要結果

`success_at_budget`：在指定預算內，通過獨立完整農場驗收的任務比例。無效設計、超時與零產出都留在分母。

`cost_to_threshold`：首次被獨立確認達標時的累计成本；未達標記為截尾。不能只比較成功案例的平均成本，否則會把最難失敗刪掉。

若需要單一成本主結果，先選定主要預算軸 B，報受限達標成本 `E[min(T, B)]`，T 為首次確認達標的成本，未成功的 T 視為超出 B；同時報成功率。零成本退出的失敗不能得到漂亮的省錢分數。

其他成本軸完整列出。預算軸、門檻與品質非劣性界線若使用，均在正式測試前鎖定。沒有顯著品質差異，不等於已證明同等品質。

## 7. 次要結果與解釋證據

| 指標 | 注意事項 |
| --- | --- |
| 干預預測 | 事前鎖定；分類正確、區間覆蓋、區間寬度與 unknown 分開，不能靠無限寬區間全對 |
| 診斷正確 | 只評可辨識原因；多個解釋等價時不硬指定唯一答案 |
| 錯誤修改 | 明確 patch 與不良結果；區分暫時診斷干預和正式設計錯誤 |
| 重用伤害 | 配對成功差／成本差，重複驗證；不把單次隨機失敗當記憶因果證明 |
| 回歸 | 修正新條件後，仍應有效的舊設計是否受損 |
| 工程品質 | 產量、穩定性、資源、面積等單列；硬約束先判合規 |
| 記憶使用 | 找回／引用／執行次數只是行為描述，不是收益證明 |

成功修復可能繞開故障而非正確理解；功能分數與解釋證據分开。LLM 評審只可作輔助，需固定規則與人工校準，主要結論依執行紀錄與獨立檢查。

## 8. 統計與樣本規劃

Pilot 先估失敗率、執行成本、不同農場／seed 的變異與可負擔規模。正式樣本量依預定最小有意義效應與變異規劃，不把任意 500 題當門檻。

相同初始 snapshot／seed 形成配對區塊，但不同操作之後不保證亂數一致。以多個獨立 runs、history streams 和任務順序重跑。正式排程盡量交错各組，避免硬體或 API 時段混雜。

同一農場的 ticks、箱子物品、微小變體及共享 memory 的任務不是獨立樣本。主要推論以 family／stream replicate 分組，採配對 cluster bootstrap 或合理階層分析；family 太少時只報該測試集的效果與不確定性，不假裝得到廣泛总体信賴區間。

預註冊主要比較與多重比較處理，呈現效應量、區間和完整分布，不只挑 p 值。凍結同一候選池的排序消融，與可自行產生候選的端到端比較分開。

## 9. 失敗、排除與資源異常

提前定義 infrastructure invalid、model/tool misuse、budget exhaustion、task infeasible 與未達標。獨立確認的測試服故障可依同一政策重跑，但原 run 保留且統計故障成本；不能事後把模型失敗改判為無效試驗。

人工提示與救援單列，不算全自主成功。所有 runs 記錄，包括解析錯誤、取消、工具逾時、零產出與無法識別機制。主表列總指派、有效、無效、重跑、成功數。

## 10. 再現所需的 manifest

保存 git_sha、task／split／source hashes、game／server／mod／JDK 設定、世界初始狀態、agent／prompt／tool schema hashes、model id／API 日期／設定、arm、順序、seed、全部預算、經驗前後版本、原始觀察、設計 patch、評分器版本、失敗原因與成本。

發布可公開的逐次結果、排除理由、分析程式及完整重跑指引。第三方授權與原始遊戲程式不得因再現需要而忽略。保留測試在正式評測時隔離，不表示永遠不公開研究方法。

## 11. 對更強模型與新文獻的處理

正式實驗前重查最接近工作，記錄採用版本。不因新模型出現就只替處置組升級；同一模型內重跑主要組。某方法優勢被強模型吸收是研究結果，不應透過削弱 baseline 保住結論。

本協定受到 [MemDelta](https://arxiv.org/abs/2606.29914) 對模型、檢索與寫入成本混雜的提醒；實驗設計和數值門檻仍由本研究自行固定，不搬用其其他領域分數。
