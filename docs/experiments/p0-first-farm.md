## 1. 先完成什麼

人工跑通一座來源可用的完整農場，固定合法輸入和輸出、留原始結果並重跑波動；確認它值得進入模型診斷研究。先不建 CDET、全量語料平台或訓練模型；允許必要的小計數程式。

從第一次考慮候選就登記全部去留，不能只保存最後讓方法勝出的農場。

## 4. 公開任務与修改界線

首個研究模式為 repair_restricted，具體限制仍需實測定案。free_optimize、design_build 另立任務，不再使用含糊的 repair_optimize。

| 規格 | 待填內容 |
| --- | --- |
| 目標物、合法輸入及耗材 | 待填 |
| 輸出端及初始庫存 | 待填，如何排除舊產物 |
| 必須保留的介面／結構 | 待填工程理由，不能透露故障位置 |
| 可改範圍、材料與累積修改預算 | 待填，不只計最終方塊差 |
| 允許感測與操作 | 待實際 capability，未支援不能假定可用 |
| 公開品質回饋／提交頻率 | 待定 |
| 成功門檻 | 正常分布量測後在 dev 定案 |
| 禁止操作 | 注入成品造分、改計分器、讀私有標籤、任意 OP 或繞過工具寫世界 |

私有故障／模組標記、参考修復與驗收 seeds 另存，不將研究者工作表掛載給模型。公開任務仍需充分說明驗收要求。

## 5. 量測與完整系統

待回答：如何證明持續產出而非清初始成熟物？怎麼算淨交付、避免重複？中間能測什麼？預熱與窗口多久？如何重跑與停止？sensor 開關是否干擾行為？局部隔離是否改變負載？

先保存逐次原始資料再定窗口，不把第一次穩定當完全確定。P0 可先人工核對末端，但正式研究仍需可信計分與可追溯原始事件／會計。

## 6. 變體與耦合證據

初期 3–5 个有意義變體即可，不湊數；全部只是待驗證方向。

| 類型 | 需獨立證明 |
| --- | --- |
| 正常控制 | 波動範圍，不把自然起伏當故障 |
| 上游／收穫變化 | 真正影響生產，不是載入或計數器錯誤 |
| 運輸／交付變化 | 實際損失／積壓可量測 |
| 下游限制 | 負載確實到容量；低負載不可硬說有瓶頸 |
| 表象相似但前提不同 | 原因與舊案例不同，標籤不依 CDET 成敗 |
| 模組互動 | 上游改／不改 × 下游改／不改有可重現相依效果，沒有就標未證明 |

每項保存 patch、正常對照、實際效應、波動、可逆性、多原因／不可辨識限制及人工／自然分類。參考修復在新世界確認。簡單案例保留作工具控制，不因模型容易就刪掉。

## 7. 模型接入前必須定的內容

按 [介面規格](../plan/agent-world-interface.md) 與 [工具契約](../plan/agent-tool-contracts.md) 填：座標與半開範圍、初始概要、scan 分頁、block states、容器欄位、entity 精度、sensor 能力與保留範圍、未知／缺資料格式、單次和累計限額、時間與載入語意。

第一版以結構化查詢＋切片，先不依賴 render。模型自己的区域解釋必須引用 observation，不給人工模組圖；工具教學用獨立微型世界。

## 8. Sanity checks 與 P0 放行

零產出真為零、正常數據可人工核對、初始庫存與診斷注入不算交付、重複事件不重算、重置無殘留、越界／非法操作不提高有效分數。完整 W/G 驗收留在 [P1](p1-interface-smoke.md)，P0 不假稱全套已跑。

來源清楚、正常版可行、會計可核對、波動已觀察才進 P1。不可靠時先修候選／環境；案例不足支持互動時限制主張，不捏造 gold。
