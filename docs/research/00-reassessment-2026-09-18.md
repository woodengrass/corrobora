# 總判斷：該做什麼、不該做什麼（2026-09-18）

## 1. 結論

這個倉庫還在規劃階段：沒有可執行的服務，沒有跑過的評測。這是好事，還沒被綁死。

看完所有文獻，判斷如下：

- 約六到七成不用做：強模型自己會，或現成工具有了，或做出來是負效果。
- 兩到三成直接拿來用：開源接上即可，不用研發。
- 值得投入的只有一小塊，而且很硬：
  1. 版本真相：同一份知識在不同遊戲版本下誰對誰錯，要有一本確定的帳。
  2. 依賴失效：來源一改，哪些結論跟著錯，要能自動找出來。
  3. 三層出處：有引用、有實際影響、可重跑，三件事分開記；不知道就直說不知道。
  4. 軌跡實驗室：把每次研究的過程存下來，能重播、能比較政策好壞。

建議把「Research Memory」這個名字換掉。它會一直誤導討論，
「版本化研究帳本 + 可重播軌跡實驗室」比較貼切。

## 2. 領域在往哪走

1. 贏的是架子不是參數：長任務靠切分、暫存、子代理分工贏，不是靠更大模型 [S-M10][S-R11]。
2. 檢索只是門票：大家轉向檢索後的整理（關係視圖、多模態排版、因果圖）和把思考過程餵給檢索器 [S-M5][S-M10]。
3. 用 RL 學控制器：學「何時檢索、壓縮、折疊」，不是學知識本身 [S-R11]。
4. 推理算力重分配：短查詢更新勝過長思考，中間 token 大多可丟 [S-M10]。
5. 2M 上下文跑得動但用不好：有效長度遠小於標稱，檢索至少再活五年（成本差 250 倍）[S-M10]。

## 3. 不用做的事

查詢拆分、改寫、假設文檔、壓縮器、引文格式、矛盾標旗、基礎規劃、機制抽象、
設計點子、程式碼導航、簡單知識圖譜、整庫倒進上下文、通用寫入門控、cosine 自動合併。
每一項都有 2025–2026 證據證明已免費或負收益 [S-M3][S-M4][S-M5][S-R6]。
一句話：不要為了「模型不懂」而預先結構化，那層已經被補完了。

## 4. 直接拿來用的事

編排和會話（LangGraph）、個人事實抽取（Mem0）、時態圖 schema（Graphiti）、
檢索通用層（LlamaIndex/Haystack）、SFT/LoRA（只在行為重複時用，知識永遠走檢索）。
自研只剩：版本過濾、別名、墓碑、保序閱讀器 [S-M8][S-V7]。

## 5. 留下來做的事（按數據分開）

### 5.1 文件（中英混、術語、重疊、多版本、會過期）

切 512–800 token 帶標題和版本 → BGE-M3 稠密加稀疏 → 重排取前 15 → 保序讀。
PG 存版本、取代鏈、有效期、墓碑、別名，預設只查現行版 [S-M6][S-V1][S-V3]。
不做知識圖譜和 RAPTOR 樹 [S-M3][S-M4]。

### 5.2 程式（MC Java 全源、低歧義）

RepoMap 級輕圖 + 即時 grep/LSP + Tree-sitter，有便宜才加 scip-java，重型分析只當按需工具。
不做全量編譯、常駐 CodeQL、向量-only 搜碼（BGE-M3 在程式上輸 2 倍）[S-M6]。

### 5.3 藍圖（幾千 litematic，現在 0 個）

先收數據再建模。VLM 解析成 JSON 存 PG，caption 存向量，圖文分離。
空間索引和模擬等有數據再試 [S-C8][S-C9]。

## 6. Dream-RSI 的定位

arXiv:2609.14858 的做法：把探索樹當成模擬器，離線比較幾千種探索政策，贏的再上線 [S-R1]。
只改政策程式，不動模型。數字漂亮但樣本小、跨模型混淆，機制可信度高於數字。
對本項目：文件問答用不上（評分器便宜且不可驗證），程式和藍圖驗證用得上（執行器貴且可驗證）。

## 7. 十五個問題逐題回答

1. 整個領域往哪走？見第 2 節。
2. 強 Agent 淘汰了什麼？見第 3 節。
3. 哪些仍然有價值？版本帳、輕碼圖、混合檢索加排序、軌跡帳、評測架子。
4. 哪些是重造輪子？編排、短期記憶、抽取、通用圖、檢索層，見第 4 節。
5. 哪些有趣但研究價值不高？自動本體、通用合併、gap 路由、大小模型對比、藍圖 3D。
6. 哪些是真未解？非結構化依賴失效、模糊鍵取代、影響力缺口、重播校準、可學控制器、跨任務負遷移、藍圖先例、拒答。
7. 未來 2–5 年什麼重要？私人語料發現、持久狀態、累積經驗、出處、版本、失效、重複成本、跨會話學習、設計先例。
8. 什麼會被 GPT-7/10 吃掉？理解、拆分、長文、基礎規劃、抽象、基礎 RAG、工具、簡單抽圖、點子。
9. Research Memory 值得嗎？大詞不值得，四子問題值得（見第 1 節）。
10. Trajectory 值得嗎？有條件值得：評估貴且可驗證才做；程序重播勝語義課；政策程式勝權重。
11. 三種數據怎麼處理？分開處理，見第 5 節。
12. 從零怎麼設計？真相層先行 → 檢索 → 生命週期 → 重播實驗室；合併、本體、路由、蒸餾全降級。
13. 刪掉什麼？Memory 名詞、全量圖、重型常駐、自動合併、TTL、通用門控、本體主線、領域模型訓練。
14. 最想加什麼？依賴蘊含圖、重播加悲觀校準、三層出處加拒答、可學控制器、藍圖語料加模擬。
15. 深挖什麼題？失效前沿、重播悲觀、影響力便宜估計、記憶關閉條件、藍圖先例有效性。
